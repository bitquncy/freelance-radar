## Review

### Findings

- **high — `bot/handlers/v2/crm_handlers.py:211-225` — forged callback can complete another reminder.** `reminder_write` independently loads `reminder_id` and `client_id`, verifies only that the supplied client belongs to the caller, but never verifies `reminder.client_id == client.id`. A user who can guess another tenant's reminder ID can submit `v2r:write:<foreign_reminder_id>:<own_client_id>`; the handler then calls `complete_reminder()` on the foreign reminder while logging an interaction against the caller's client. **Fix:** require `reminder.client_id == client.id` in the authorization predicate (prefer a joined query constrained by reminder ID, client ID, and `Client.user_id`), and add a cross-tenant/mismatched-pair regression test.

- **medium — `bot/handlers/v2/proposals.py:106-118, 331-360` — project callback IDs are accepted without tenant/source authorization.** `proposal_generate` and `proposal_cases` fetch a global `Project` by raw callback ID and do not establish that the project is visible through the caller's `ExchangeConnection`; callback data can be forged. This lets one tenant generate proposals/adapt portfolio against another tenant's collected project and expose its title/description in the resulting message. (`Proposal` ownership checks later do not repair this initial disclosure.) **Fix:** load the project through an ownership-scoped query joining its source connection to `user.id`, or explicitly model globally shared projects and authorize visibility; add forged foreign-project callback tests.

- **medium — `bot/handlers/v2/proposals.py:320-328` — forged hide callback is not authenticated or bound to a project.** The handler ignores callback data and effective user and deletes whichever bot message carries a matching `v2p:hide:<id>` payload. It performs neither subscription nor project visibility checks. This is mainly an integrity/authorization inconsistency rather than data disclosure, but it makes the callback ID meaningless and permits expired/non-entitled users to execute the action. **Fix:** require `effective_user`, parse the ID, authorize project visibility, then delete; alternatively use a non-ID callback and document hide as purely local UI behavior.

- **medium — `bot/handlers/v2/sources.py:208` — empty/whitespace pending input crashes the update.** `text.strip().split()[0]` raises `IndexError` for whitespace-only messages. The global handler only logs the exception (`main.py:117-122`), so the user receives no recovery response; additionally the router popped `v2_add_channel` before calling this function (`bot/handlers/v2/router.py:27`), so the FSM-like flow is lost and the next reply is ignored. **Fix:** validate `parts` before indexing and keep/re-set pending state on validation errors; test blank and whitespace-only input.

- **low — `bot/handlers/settings_handler.py:234` — emoji status renders literal template text.** The nested expressions are quoted strings, so the UI displays `{P.CHECK}` / `{P.CROSS}` instead of ✅ / ❌. **Fix:** compute `status = P.CHECK if ... else P.CROSS` and interpolate `status`; add rendering assertion.

- **low — `main.py:117-122` — unexpected Telegram handler failures are logged without traceback or user recovery.** Logging only `str(context.error)` removes stack evidence needed to diagnose runtime failures, and no safe reply/alert is attempted. The whitespace crash above therefore becomes silent from the user's perspective and hard to localize operationally. **Fix:** use exception logging (`logger.exception` or `exc_info=context.error`, according to the logger wrapper), include update metadata without sensitive text, and best-effort notify the originating callback/message.

### Checked without findings

- Ownership checks are present for proposal edit/regenerate/send, portfolio deletion, source toggle/delete, CRM client view/stage/note, and reminder snooze.
- Callback handler regexes are anchored for the inspected V2 handlers and numeric IDs are constrained before integer parsing.
- Telegram Payments revalidates signed application payload semantics and amount at both pre-checkout and successful-payment stages; application is idempotent by charge ID in the tested flow.
- V2 HTML cards escape user/scraped fields through `esc()` (project title/summary/flags, proposal text/violations, portfolio content, client notes/interactions) and restrict project links to HTTP(S).
- Premium emoji separation is structurally sound: `E.*` is intended for HTML message text, while `P.*`/button helpers remain plain Unicode. `scripts/audit_emoji.py` found no `E.*` use in buttons/alerts.
- Owner-only decorators cover inspected legacy administrative handlers and `/grant`; V2 user commands intentionally remain available to non-owner tenants.
- Conversation persistence is enabled for V2 with `PicklePersistence`; portfolio add has `/cancel`, and pending proposal/note operations recheck ownership at apply time.

### Test gaps / residual risks

- No observed regression test for a mismatched `reminder_id` + caller-owned `client_id` pair in `reminder_write`.
- No observed forged foreign-project tests for `proposal_generate` / `proposal_cases`, nor authorization test for `proposal_hide`.
- No blank/whitespace TG-channel input test covering pending-state retention.
- Global error-handler behavior (traceback capture and user-facing recovery) is not meaningfully exercised.
- Full pytest could not be run because `pytest` is unavailable in the execution environment. `compileall` passed, so syntax/import compilation alone does not establish runtime correctness.
- Requested `plan.md` and repo-root `progress.md` were absent. Review-only instructions prohibited changing the external progress artifact, so it was not updated.
